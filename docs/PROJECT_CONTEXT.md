# 딸기마을 작업 맥락

2026년 11월 8일 기준. 모바일, 노트북, ChatGPT Work와 Dot에서 같은 원본과 사용자 결정을 바탕으로 작업하기 위한 문서다.

## 서비스와 원본

- 공개 주소: https://strawberry-village.web.app/
- 공개 원본 저장소: https://github.com/redbee-robotics/strawberry-village
- 쓰기 권한이 있는 참여자는 포크 없이 원본 저장소의 새 브랜치에서 main으로 PR을 보낸다. 포크를 필수로 안내하지 않는다. 쓰기 권한이 없는 사람은 접근 권한을 요청하거나 자신의 포크에서 PR을 보낼 수 있다. 기여 절차는 `CONTRIBUTING.md`에 있다.
- Firebase 프로젝트: `strawberry-village`
- Firebase Hosting 대상: `village`
- Realtime Database 대상: `village`, 인스턴스 `strawberry-village-default-rtdb`, asia-southeast1 리전
- 사이트 이름: 딸기마을. 공유 설명: **온라인 딸기 농장. 함께 딸기를 키우고 수확해보세요.**

원본 코드는 정적 React/Vite 및 Three.js 앱이다. 최신 원본은 redbee-robotics 조직의 공개 GitHub 저장소에서 관리한다. 공개 서비스는 Firebase Hosting을 사용한다. Sites에 먼저 저장한 비공개 버전과 안내 페이지의 압축 파일은 백업이다. 사용자가 배포를 요청할 때만 Firebase에 게시한다. 외부 PR 작성이나 병합만으로 자동 배포하지 않는다. 평소 수정은 개발 화면에서 확인하고 저장한다.

사용자 요청에 따라 GitHub Release 게시 시 `.github/workflows/release.yml`에서 해당 태그의 타입·재고·이동 경로 검사와 빌드를 수행한 뒤 Firebase Hosting `village`에 배포한다. PR 작성·병합과 태그 push는 배포하지 않는다. Release를 대신 게시하려면 별도 사용자 요청이 필요하다. 인증에는 저장소 Actions secret `FIREBASE_SERVICE_ACCOUNT_STRAWBERRY_VILLAGE`가 필요하며, 최초 설정은 `docs/RELEASES.md`에 정리한다.

다른 기기와 Dot에서는 GitHub 저장소의 최신 main 브랜치를 불러온다. 비공개 Sites 백업을 사용해야 할 때는 `.openai/hosting.json`에 있는 프로젝트 ID와 Sites의 소스 열기 절차를 사용하되, GitHub의 이후 변경을 오래된 백업으로 덮어쓰지 않는다. 새 환경에 이 PC의 파일이나 로그인 정보가 있다고 가정하지 않는다. Firebase 배포에는 프로젝트 접근 권한이 있는 계정으로 새 환경에서 별도 로그인이 필요하다. 기존 로그인 토큰이나 서비스 계정 키는 업로드하지 않았다.

## 사용자 결정

### 마을과 공간

온라인 산사 `sansatemple.com`에서 영감을 받은 작은 3D 마을이다. 논밭과 그 사이 길, 네 동의 딸기 하우스, 딸기 선별장, 딸기 카페가 있다. 논밭에도 걸어 들어갈 수 있다. 장터는 만들지 않는다.

하우스, 카페, 선별장에 걸어 들어가면 그 공간만 있는 별도의 3D 실내 화면으로 바뀐다. 입장 메뉴나 자동 이동 버튼은 없다. 밖으로 걸어 나오면 마을의 원래 카메라 시점으로 돌아간다. 카페 입장 시 지붕을 없애는 방식은 사용하지 않는다.

하우스 네 동은 좌우와 앞뒤 간격을 넓힌다. 옆면과 뒷면을 통과하지 못하며 앞문으로만 출입한다. 입구에서 통로로 돌아설 공간을 확보하도록 베드를 조금 줄였다. 선별장 옆 적재 상자에도 충돌 처리를 적용한다. 야외를 클릭하면 다른 건물 안을 지름길로 통과하지 않고 우회하며, 건물 내부를 선택했을 때만 그 건물로 경로를 연다. 야외 카페 메뉴판과 ‘카페 메뉴’ 이름표는 제거한다.

이동 범위는 좌우 70, 앞쪽 50, 뒤쪽 92까지 넓혔다. 뒷산은 연속 높이 지형이며 오르막 산책길을 따라 정상까지 이동한다. 스페이스바로 점프하며 외벽과 상자를 점프로 관통하지 않는다. 새로고침이나 재접속 시 현재 브라우저의 마지막 위치·방향·공간·시야를 복원한다.

레이블은 **딸기 하우스**, **딸기 선별장**, **딸기 카페**로 한다. 하우스 번호를 표시하지 않는다. 카페 레이블에 딸기 라떼를 덧붙이지 않는다. 카페에는 점원이 있다. 점원 외에는 실제 접속한 사람만 보이며 돌아다니는 NPC는 없다.

야외 장소 레이블은 화면 기준 크기의 HTML로 표시해 카메라 거리와 화면 크기에 따라 작아지지 않게 한다. 서로 겹치지 않게 배치하고 화면 안쪽으로 보정하며, 연결선으로 실제 장소를 가리킨다. 레이블을 눌러도 해당 장소로 걸어간다.

글씨는 충분히 진하고 읽을 수 있는 크기로 유지한다. 다음 문구를 다시 추가하지 않는다: 잠깐 초록 곁에, 오늘은 아무것도 서두르지 않기로 해요, 논길 따라 딸기마을, 논밭 사이 작은 농장 마을.

### 조작과 행동

| 조작 | 동작 |
| --- | --- |
| 방향키 | 걷기 |
| 화면 클릭 또는 터치 | 누른 위치로 걷기. 건물과 재배대를 돌아가며, 막힌 위치는 가장 가까운 빈 바닥으로 이동 |
| 좌클릭 드래그 | 화면 회전 |
| 우클릭 드래그 | 화면 이동 |
| 마우스 휠 | 확대 축소 |
| 모바일 한 손가락 드래그 | 화면 회전 |
| 모바일 두 손가락 드래그 / 핀치 | 화면 이동 / 확대 축소 |

WASD와 모바일 조이스틱은 사용하지 않는다. 드래그와 여러 손가락 제스처는 클릭 이동으로 처리하지 않는다. 방향키 입력, 모달 열기, 행동 시작 시 클릭 이동을 멈춘다. 공간이 전환되어도 선택한 목적지까지 이어서 걷는다. 행동을 선택해도 캐릭터가 알아서 걸어가지 않는다. 마을 지도에 이동키 안내를 넣지 않는다.

마을 지도는 기본으로 왼쪽 아래의 최소화된 표시줄로 보인다. **바구니**와 **가방**은 오른쪽 아래에 바구니 먼저, 가방이 그 아래에 오도록 표시한다. 모바일에서는 가방·바구니 카드, 스킬, 확대·축소, 상단 도구의 아이콘과 여백을 줄여 마을을 넓게 보여준다. 행동 버튼은 왼쪽 아래에 두고, 조건부 행동이 늘어나면 줄을 바꿔 가방과 바구니를 가리지 않는다. 화면 하단 안전 영역을 확보한다.

확대·축소 버튼은 모든 화면에서 기본으로 숨기고 마을 설정의 스위치로 표시한다. 이 선택은 현재 브라우저에 저장한다. 모바일은 두 손가락 드래그로 우클릭 드래그와 같은 화면 이동을 하고, 핀치로 확대·축소한다.

지도 조작은 상단 나침반 대신 왼쪽 아래의 작은 ‘마을 지도’ 창에서 펼치기·최소화한다. 기본은 최소화된 표시줄이다. 이용 안내의 ‘좋아요, 천천히 둘러볼게요’ 확인 버튼은 제거하고 닫기 버튼만 사용한다.

이용 안내에는 `https://github.com/redbee-robotics/strawberry-village` 링크와 **당신도 딸기마을에 기여할 수 있어요.** 문구를 표시한다.

| 표시 순서 | 행동 | 표시 및 사용 조건 |
| --- | --- | --- |
| 1 | 물 주기 | 고설 딸기 베드 가까이 |
| 2 | 수확 | 고설 베드와 익은 딸기 가까이 |
| 조건부 | 앉기 | 의자 가까이 |
| 조건부 | 눕기 | 누울 수 있는 평상 가까이 |
| 조건부 | 살펴보기 | 고설 베드 가까이, 잎과 꽃과 열매를 가까이 보는 시점 |

행동 번호와 숫자키는 현재 화면에 보이는 순서대로 1부터 붙인다. 물 주기와 수확 다음에 나타나는 앉기·눕기·살펴보기는 빈 번호 없이 이어진다. 앉거나 누운 상태에서 같은 번호를 누르거나 걷기 시작하면 일어난다. 살펴보기도 표시된 같은 번호나 이동으로 종료한다. 일반적인 쉬기 행동은 없다. 선별하기나 카페 들어가기 행동 버튼도 없다.

도착이나 행동 안내는 약 3.8초 후 사라져야 한다. 베드 근처에서 사용할 수 있다는 문구나 도착 메시지를 계속 노출하지 않는다.

### 수확과 포장

수확한 딸기 낱알은 **바구니**에 넣는다. 포장된 딸기 팩은 **가방**에 넣는다. 바구니 제목은 나의 작은 수확을 사용하지 않는다.

선별장에 걸어 들어가면 하나로 합쳐진 작업 화면이 열린다. 사용자가 바구니의 딸기 네 알을 팩에 선택해 담는다. 선택한 딸기를 바구니로 되돌릴 수 있다. 선별 완료 시 낱알 네 알이 한 번만 차감되고 포장된 1팩이 가방에 추가된다. 분류와 상자 담기를 별도 단계나 스킬로 나누지 않는다.

딸기는 클릭·숫자키 접근을 유지하면서 마우스와 터치 드래그로 지정한 칸에 넣고, 칸 사이를 이동·교환하거나 바구니로 돌려놓을 수 있다. 이동 중에는 원본 재고를 차감하지 않는다. 포장 완료 시에만 네 알을 한 번 소비한다. 새 팩은 내용물도 함께 저장한다.

카페에서는 바구니와 가방의 모든 딸기를 합산해 딸기 라떼 2알, 딸기 우유 1알, 딸기 차 1알을 주문한다. 1팩은 4알이다. 낱알이 부족하면 필요한 만큼의 팩을 열고 남은 딸기는 바구니로 보낸다. 예전 저장 데이터의 라떼용 낱알도 합산한다. 음료 받기를 누르면 캐릭터가 컵을 들며 컵도 재접속 시 복원한다. 실제 결제는 없다. 저장 복원 시 바구니를 2천 알로 잘라내던 제한은 재고 숫자 상한과 같은 10만 알로 늘렸다.

수확과 포장 재고는 현재 브라우저의 로컬 저장소에 저장한다. 기기 간 재고 공유 기능은 아직 없다. 코드의 클라우드 저장과 게임 재고 동기화는 별개다.

### 동시 접속

사용자가 Firebase 익명 로그인과 Realtime Database 사용을 승인했다. 브라우저 세션별 이름, 위치, 방향, 행동, 바구니 수량, 현재 공간을 공유한다. 접속자는 자신의 상태만 쓸 수 있다. 접속 종료 처리를 등록하고 연결이 끊기면 해당 상태를 지운다. 데이터 규칙은 `database.rules.json`에 있다.

이름은 햇살 한 줌, 딸기향 오후, 산들바람 같은 읽을 수 있는 한국어 문구로 한다. 임의의 16진수 문자열을 표시하거나 농부라는 접미사를 강제하지 않는다. 접속 인원과 마을 연결 중 표시가 계속 번갈아 깜빡이지 않도록 현재의 연결 확인과 재시도 처리를 유지한다. 다른 실내에 있는 사람은 같은 화면에 표시하지 않는다.

설정에서 1~16자 닉네임을 변경한다. 접속자 스냅샷을 읽은 뒤 참가하고, 동시 접속 중복은 세션 정렬과 짧은 숫자 접미사로 결정적으로 구분한다. 사용 중인 이름을 직접 선택하면 거부한다. 이름표는 안개와 화면의 밝은 막에 흐려지지 않는 진한 HTML로 표시한다. 이 기능은 앱의 세션 집계와 표시 계층에서 처리하며 별도의 서버 예약 레지스트리는 사용하지 않는다. 접속 수는 사람 수가 아닌 브라우저 세션 수이며 공개·개발·비공개 확인 화면이 같은 데이터베이스를 공유한다.

확장 좌표는 v2 세션의 전송 시 x를 2, z를 3으로 나누어 기존 데이터베이스 범위 안에 보낸다. 새 클라이언트는 이를 복원하며 이전 세션의 원래 좌표도 읽는다. 이전 클라이언트는 새 전송 형식을 해석하지 못하므로 서로 다른 버전 사이에서는 방문자 위치가 다르게 보일 수 있다. 점프의 세로 움직임은 로컬 동작이며 다른 방문자의 높이는 지형으로 계산한다.

### 날씨와 시야

날씨는 논산의 현재 날씨 자료를 Open-Meteo에서 가져온다. 고정 좌표는 36.20389, 127.08472이며 사용자의 실제 위치 권한은 요청하지 않는다. 사용자가 날씨나 낮밤을 임의로 바꾸지 않는다. 모델 기반 현재 날씨 자료이므로 현장 관측 센서 데이터라고 설명하지 않는다.

화면에는 위치명 논산을 표시하지 않는다. 상단에는 날씨 상태와 기온을 보여주되, 마을 설정에는 현재 날씨, 습도, 바람, 강수량을 표시하지 않는다. 날씨와 낮밤에 맞춰 마을이 바뀐다는 설명, 기준 시각과 Open-Meteo 출처 문구도 표시하지 않는다. 움직임 줄이기 옵션은 UI에 추가하지 않는다. 운영체제의 관련 선호는 자동 적용한다.

카페·하우스는 시야를 더 넓히고 입장 위치에서 카메라를 물려 사람과 베드가 과하게 크게 보이지 않게 했다. 시야각은 카페 82도/모바일 90도, 하우스 78도/모바일 86도, 선별장 72도/모바일 80도다. 선별장은 앞뒤 어느 쪽 입장에서도 같은 대각선 시점을 사용한다. 이름표는 거리와 무관한 화면 크기를 유지한다.

## 실행과 확인

Node.js 22.13 이상에서 `npm ci` 후 `npm run dev`를 실행한다. 기본 주소는 http://127.0.0.1:5173/ 이다. `npm run build`는 Firebase와 클라우드 저장 버전에서 공통으로 쓰는 정적 `build/` 폴더를 생성한다.

개발 서버는 Vite HMR과 React Fast Refresh를 사용한다. 클라우드 파일 시스템에서도 변경을 감지하도록 파일 감시에 300ms 폴링을 사용한다.
클라우드 미리보기에서 접근할 수 있도록 `0.0.0.0:5173`에서 수신하며, 브라우저 주소는 `http://127.0.0.1:5173/`을 사용한다. 개발 응답은 캐시하지 않는다.
클라우드 환경의 localhost와 사용자 기기의 localhost는 서로 다른 서버다. 클라우드에서 개발 서버를 실행한 것으로 사용자 기기의 로컬 화면이 갱신되었다고 안내하지 않는다. 로컬 화면을 갱신하려면 해당 기기의 저장소에 변경 브랜치를 받아 그 기기의 서버에서 실행해야 한다.
`/__dev/status`는 3D와 React를 사용하지 않는 개발 전용 연결 확인 화면이다. 이 화면까지 비어 있다면 앱 기능보다 브라우저 미리보기의 서버 연결을 먼저 확인한다. 프로덕션 빌드에는 이 경로를 포함하지 않는다.

타입 검사: `node node_modules/typescript/bin/tsc --noEmit`

클릭 이동 경로 검사: `node scripts/validate-navigation.mjs`. 직선 이동, 범위 제한, 장애물 클릭, 얇은 벽 우회, 베드 사이 좁은 통로, 도달 불가능한 위치를 확인한다.

마을 상태 검사: `node scripts/validate-village.mjs`. 닉네임 중복 해소와 입력 순서 독립성, 좌표 전송 호환과 범위, 산 지형의 연속성과 오르막 산책길을 확인한다.

재고 검사: `node scripts/validate-inventory.mjs`

검사 범위는 불완전하거나 중복된 선택 거부, 없는 딸기 거부, 원자적인 포장, 같은 딸기 중복 소비 방지, 카페에서 팩을 열어 소비하고 남은 낱알을 보존하는지, 이전 저장 데이터 변환이다.

기존에 실제 브라우저에서 걷기, 가까운 베드의 물 주기와 수확, 네 알 포장과 가방 추가, 카페 주문, 앉기와 눕기, 두 접속자의 공유를 확인했다. 독립된 하우스 실내, 베드 살펴보기, 실제 날씨 표시와 위치명 숨김, 카페 시점도 확인한 바 있다.

이번 변경에서는 타입 검사, 재고·이동 경로 검사, 정적 빌드와 Release 워크플로 YAML 검사를 통과했다. 브라우저에서 클릭 도착·목적지 변경, 방향키·모달로 이동 취소, 드래그·우클릭·여러 손가락 제스처 구분, 지도 토글, 이름·순서·설정·기여 안내를 확인했다. 320×568, 390×844, 760×390에서 장소 레이블 8개의 가독성·겹침·잘림과 조작 UI 배치를 확인했다. 소프트웨어 GPU 부하를 분리해 동작 검사를 실행하고, 실제 렌더러와 원래 해상도·그림자로 모바일 화면을 별도 확인했다. HMR WebSocket 연결과 CSS 저장 시 갱신 이벤트도 확인했다. 사용자의 인앱 브라우저에서 개발 전용 연결 확인 경로 대신 게임이 표시되어 서로 다른 서버에 연결되어 있음을 확인했다. 사용자 기기의 로컬 서버를 직접 갱신하지는 못했다. 공개 서비스 배포와 Release 게시는 진행하지 않았다.

추가 변경에서는 타입 검사, 재고·경로·마을 상태 검사와 정적 빌드를 통과했다. 브라우저에서 지정 칸으로 드래그, 칸 교환과 바구니 반환, 포장 시 한 번 차감, 카페의 팩 합산·개봉과 남은 낱알, 야외 목적지로 이동할 때 선별장 우회, 하우스 측면·후면 충돌과 앞문 통과, 적재 상자 충돌, 선별장 양쪽 입구의 같은 시점, 표시 순서와 숫자키 일치, 산 정상 높이와 점프, 실내·야외 위치와 들고 있는 음료 복원을 확인했다. 확대·축소 버튼의 기본 숨김·설정 표시·새로고침 유지와 모바일의 두 손가락 이동·핀치·딸기 드래그도 확인했다. 기능 검사는 렌더링 부하를 분리했으며 실제 렌더러로 마을·하우스·카페·선별장 화면을 별도로 확인했다. 닉네임의 결정적 중복 해소는 상태 검사로 검증했으며 서버의 원자적 이름 예약은 구현하지 않았다. 자동 검사에서는 외부 인증 연결을 막아 실제 접속 수를 늘리지 않았다.

## 다음 작업의 기본 흐름

1. GitHub 저장소의 최신 main 브랜치를 열고 이 문서와 AGENTS.md를 읽는다.
2. 사용자가 요청한 부분을 수정하고 개발 화면과 해당 검사를 확인한다.
3. 변경된 작업 맥락을 갱신하고 GitHub에 소스를 저장한다. 쓰기 권한이 있는 참여자는 원본의 작업 브랜치에서 main으로 PR을 보낸다. 권한이 없는 참여자는 권한을 요청하거나 자신의 포크에서 PR을 보낸다.
4. 사용자가 배포를 요청한 경우에만 인증 상태를 확인하고 Firebase Hosting의 village 대상에 배포한다. 별도 요청 없이 Sites에 게시하거나 공개 서비스를 옮기지 않는다.
