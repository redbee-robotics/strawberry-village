# 딸기마을 작업 맥락

2026년 11월 8일 기준. 모바일, 노트북, ChatGPT Work와 Dot에서 같은 원본과 사용자 결정을 바탕으로 작업하기 위한 문서다.

## 서비스와 원본

- 공개 주소: https://strawberry-village.web.app/
- 공개 원본 저장소: https://github.com/redbee-robotics/strawberry-village
- 쓰기 권한이 있는 참여자는 포크 없이 원본 저장소의 새 브랜치에서 main으로 PR을 보낸다. 포크를 필수로 안내하지 않는다. 쓰기 권한이 없는 사람은 접근 권한을 요청하거나 자신의 포크에서 PR을 보낼 수 있다. 기여 절차는 `CONTRIBUTING.md`에 있다.
- Firebase 프로젝트: `strawberry-village`
- Firebase Hosting 대상: `village`
- Realtime Database 대상: `village`, 인스턴스 `strawberry-village-default-rtdb`, asia-southeast1 리전
- 사이트 이름: 딸기마을. 공유 설명: **온라인 딸기 농장. 함께 딸기를 키우고 수확해보세요.**

원본 코드는 정적 React/Vite 및 Three.js 앱이다. 최신 원본은 redbee-robotics 조직의 공개 GitHub 저장소에서 관리한다. 공개 서비스는 Firebase Hosting을 사용한다. Sites에 먼저 저장한 비공개 버전과 안내 페이지의 압축 파일은 백업이다. 사용자가 배포를 요청할 때만 Firebase에 게시한다. 외부 PR 작성이나 병합만으로 자동 배포하지 않는다. 평소 수정은 개발 화면에서 확인하고 저장한다.

사용자 요청에 따라 GitHub Release 게시 시 `.github/workflows/release.yml`에서 해당 태그의 타입·재고·이동 경로 검사와 빌드를 수행한 뒤 Firebase Hosting `village`에 배포한다. PR 작성·병합과 태그 push는 배포하지 않는다. Release를 대신 게시하려면 별도 사용자 요청이 필요하다. 인증에는 저장소 Actions secret `FIREBASE_SERVICE_ACCOUNT_STRAWBERRY_VILLAGE`가 필요하며, 최초 설정은 `docs/RELEASES.md`에 정리한다.

다른 기기와 Dot에서는 GitHub 저장소의 최신 main 브랜치를 불러온다. 비공개 Sites 백업을 사용해야 할 때는 `.openai/hosting.json`에 있는 프로젝트 ID와 Sites의 소스 열기 절차를 사용하되, GitHub의 이후 변경을 오래된 백업으로 덮어쓰지 않는다. 새 환경에 이 PC의 파일이나 로그인 정보가 있다고 가정하지 않는다. Firebase 배포에는 프로젝트 접근 권한이 있는 계정으로 새 환경에서 별도 로그인이 필요하다. 기존 로그인 토큰이나 서비스 계정 키는 업로드하지 않았다.

## 사용자 결정

### 마을과 공간

온라인 산사 `sansatemple.com`에서 영감을 받은 작은 3D 마을이다. 논밭과 그 사이 길, 여섯 동의 딸기 하우스, 딸기 선별장, 딸기 카페가 있다. 논밭에도 걸어 들어갈 수 있다. 장터는 만들지 않는다.

하우스, 카페, 선별장에 걸어 들어가면 그 공간만 있는 별도의 3D 실내 화면으로 바뀐다. 입장 메뉴나 자동 이동 버튼은 없다. 밖으로 걸어 나와도 캐릭터를 중심으로 한 가까운 3인칭 시점과 회전 방향을 유지한다. 카페 입장 시 지붕을 없애는 방식은 사용하지 않는다.

기존 하우스는 좌우와 앞뒤 간격을 넓히고 바깥 좌우에 두 동을 더 배치했다. 논밭은 17개 구획으로 늘리고 농로를 연결한다. 하우스 옆면은 통과하지 못하며 앞뒤 가운데 문으로 출입한다. 입구에서 통로로 돌아설 공간을 확보하도록 베드를 조금 줄였다. 선별장 옆 적재 상자에도 충돌 처리를 적용한다. 야외를 클릭하면 다른 건물 안을 지름길로 통과하지 않고 우회하며, 건물 내부를 선택했을 때만 그 건물로 경로를 연다. 야외 카페 메뉴판과 ‘카페 메뉴’ 이름표는 제거한다.

이동 범위는 좌우 70, 앞쪽 50, 뒤쪽 92까지 넓혔다. 뒷산은 연속 높이 지형이며 오르막 산책길을 따라 정상까지 이동한다. 스페이스바로 점프하며 외벽과 상자를 점프로 관통하지 않는다. 새로고침이나 재접속 시 현재 브라우저의 마지막 위치·방향·공간·시야를 복원한다.

레이블은 **딸기 하우스**, **딸기 선별장**, **딸기 카페**로 한다. 하우스 번호를 표시하지 않는다. 카페 레이블에 딸기 라떼를 덧붙이지 않는다. 카페에는 점원이 있다. 공개 서비스는 점원 외에 실제 접속한 사람만 표시한다. 사용자가 요청한 채팅 테스트를 위해 개발 미리보기의 `/dev/`에서만 캐릭터 근처에 “테스트 이웃” 한 명을 표시한다. 이 이웃은 로컬 테스트 응답을 보내며 실제 접속 인원이나 Firebase 세션에는 포함하지 않는다.

야외 장소 레이블은 화면 기준 크기의 HTML로 표시해 카메라 거리와 화면 크기에 따라 작아지지 않게 한다. 서로 겹치지 않게 배치하고 화면 안쪽으로 보정하며, 연결선으로 실제 장소를 가리킨다. 레이블을 눌러도 해당 장소로 걸어간다.

글씨는 충분히 진하고 읽을 수 있는 크기로 유지한다. 다음 문구를 다시 추가하지 않는다: 잠깐 초록 곁에, 오늘은 아무것도 서두르지 않기로 해요, 논길 따라 딸기마을, 논밭 사이 작은 농장 마을.

### 조작과 행동

| 조작 | 동작 |
| --- | --- |
| 방향키 | 걷기 |
| 화면 클릭 또는 터치 | 누른 위치로 걷기. 건물과 재배대를 돌아가며, 막힌 위치는 가장 가까운 빈 바닥으로 이동 |
| 좌클릭 드래그 | 캐릭터 중심으로 시점 회전 |
| 우클릭 드래그 | 캐릭터 중심으로 시점 회전 |
| 마우스 휠 | 확대 축소 |
| 모바일 한 손가락 드래그 | 캐릭터 중심으로 시점 회전 |
| 모바일 두 손가락 드래그 / 핀치 | 시점 회전 / 가까운 범위에서 확대 축소 |

WASD와 모바일 조이스틱은 사용하지 않는다. 드래그와 여러 손가락 제스처는 클릭 이동으로 처리하지 않는다. 방향키 입력, 모달 열기, 행동 시작 시 클릭 이동을 멈춘다. 공간이 전환되어도 선택한 목적지까지 이어서 걷는다. 행동을 선택해도 캐릭터가 알아서 걸어가지 않는다. 마을 지도에 이동키 안내를 넣지 않는다.

마을 지도는 기본으로 왼쪽 맨 아래의 최소화된 표시줄로 보인다. 하단 안전 영역을 포함해 18px 이상 여백을 두고, 모바일 행동 버튼은 지도 위쪽에 배치한다. **바구니**와 **가방**은 같은 높이의 카드로 오른쪽 아래에 바구니 먼저, 가방이 그 아래에 오도록 표시한다. 모바일에서는 가방·바구니 카드, 스킬, 확대·축소, 상단 도구의 아이콘과 여백을 줄여 마을을 넓게 보여준다. 행동 버튼은 왼쪽 아래에 두고, 조건부 행동이 늘어나면 줄을 바꿔 가방과 바구니를 가리지 않는다. 행동 버튼은 순서와 글자 길이에 관계없이 같은 크기이며 네 번째 버튼만 넓히지 않는다. 화면 하단 안전 영역을 확보한다.

확대·축소 버튼은 모든 화면에서 기본으로 숨기고 설정의 스위치로 표시한다. 이 선택은 현재 브라우저에 저장한다. 모바일은 한 손가락이나 두 손가락 드래그로 캐릭터 주위를 회전하고 핀치로 가까운 범위에서 확대·축소한다. 화면만 따로 이동하는 팬 기능은 없다.

왼쪽 상단의 로고·딸기마을 제목·영문 부제는 표시하지 않는다. 설정 화면의 제목은 ‘설정’이며, 입력칸에서 시작한 텍스트 드래그가 바깥에서 끝나도 설정을 닫지 않는다. 배경을 직접 짧게 클릭한 경우에만 닫는다. 처음 시점으로 돌아가는 버튼은 설정과 확대·축소 조절부에서 제거한다. 지도 범례에는 ‘딸기 하우스’만 표시하고 동수를 쓰지 않는다. 지도 그림의 하우스·선별장·카페는 글자 대신 하우스·상자·커피 아이콘으로 표시한다. 모바일과 데스크톱 모두 같은 아이콘 지도를 펼치며, 모바일에서 그림을 숨기지 않는다. 화면 높이가 낮을 때는 지도 칸의 높이를 줄인다.

지도 조작은 상단 나침반 대신 왼쪽 아래의 작은 ‘마을 지도’ 창에서 펼치기·최소화한다. 기본은 최소화된 표시줄이다. 이용 안내의 ‘좋아요, 천천히 둘러볼게요’ 확인 버튼은 제거하고 닫기 버튼만 사용한다.

이용 안내에는 `https://github.com/redbee-robotics/strawberry-village` 링크와 **당신도 딸기마을에 기여할 수 있어요.** 문구를 표시한다.

| 표시 순서 | 행동 | 표시 및 사용 조건 |
| --- | --- | --- |
| 조건부 | 물 주기 | 하우스 안의 고설 딸기 베드 가까이 |
| 조건부 | 수확 | 하우스 안의 고설 베드와 익은 딸기 가까이 |
| 조건부 | 앉기 | 의자 가까이 |
| 조건부 | 눕기 | 누울 수 있는 평상 가까이 |
| 조건부 | 살펴보기 | 고설 베드 가까이, 잎과 꽃과 열매를 가까이 보는 시점 |
| 조건부 | 마시기 | 카페에서 받은 음료를 들고 있을 때 |

행동 번호와 숫자키는 현재 화면에 보이는 순서대로 1부터 붙인다. 물 주기와 수확은 하우스 밖에서는 표시하지 않으며 벽 너머의 베드에도 사용할 수 없다. 앉기·눕기·살펴보기·말 걸기는 빈 번호 없이 이어진다. 앉거나 누운 상태에서 같은 번호를 누르거나 걷기 시작하면 일어난다. 살펴보기도 표시된 같은 번호나 이동으로 종료한다. 일반적인 쉬기 행동은 없다. 선별하기나 카페 들어가기 행동 버튼도 없다.

도착이나 행동 안내는 약 3.8초 후 사라져야 한다. 베드 근처에서 사용할 수 있다는 문구나 도착 메시지를 계속 노출하지 않는다.

### 수확과 포장

수확한 딸기 낱알은 **바구니**에 넣는다. 포장된 딸기 팩은 **가방**에 넣는다. 바구니 제목은 나의 작은 수확을 사용하지 않는다.

선별장에 걸어 들어가면 하나로 합쳐진 작업 화면이 열린다. 사용자가 바구니의 딸기 12알을 팩에 선택해 담는다. 선택한 딸기를 바구니로 되돌릴 수 있다. 선별 완료 시 낱알 12알이 한 번만 차감되고 포장된 1팩이 가방에 추가된다. 분류와 상자 담기를 별도 단계나 스킬로 나누지 않는다.

딸기는 클릭·숫자키 접근을 유지하면서 마우스와 터치 드래그로 지정한 칸에 넣고, 칸 사이를 이동·교환하거나 바구니로 돌려놓을 수 있다. 이동 중에는 원본 재고를 차감하지 않는다. 포장 완료 시에만 12알을 한 번 소비한다. 새 팩은 내용물도 함께 저장한다. 12칸은 4열 3행이며 작은 화면에서 드래그 중 모달 가장자리에 닿으면 스크롤한다. 선별장에는 반복된 드래그 안내, 바구니 옆 안내, 팩 가운데 오늘의 수확 장식 문구를 표시하지 않는다.

카페에서는 바구니와 가방의 모든 딸기를 합산해 딸기 라떼 2알, 딸기 우유 1알, 딸기 차 1알을 주문한다. 새 팩은 12알이다. 기존 4알 팩은 그대로 보존하며 저장된 실제 내용물 수로 합산한다. 내용물이 기록되지 않은 예전 팩은 4알로 취급한다. 낱알이 부족하면 필요한 만큼의 팩을 열고 남은 딸기는 바구니로 보낸다. 예전 저장 데이터의 라떼용 낱알도 합산한다. 음료 받기를 누르면 캐릭터가 컵을 들며 컵도 재접속 시 복원한다. 받은 음료가 있으면 하단에 마시기 버튼과 숫자키가 표시된다. 누르면 컵을 입으로 가져가 약 1.8초 동안 마시고, 완료 후 컵·상단 음료 이름·마시기 버튼과 저장된 보유 음료 키를 지운다. 걷기·점프·모달 열기·다른 행동으로 취소하면 음료를 소비하지 않는다. 마시기는 딸기를 추가로 차감하지 않으며, 기존 음료를 마치기 전에는 새 주문으로 덮어쓰지 않는다. 마시기 애니메이션은 로컬 표시이며 서버에는 기존 규칙과 호환되는 cafe 상태로 전송한다. 실제 결제는 없다. 저장 복원 시 바구니를 2천 알로 잘라내던 제한은 재고 숫자 상한과 같은 10만 알로 늘렸다.

바구니에는 누적 수확량·물 주기 횟수를 표시하지 않는다. 가방 하단의 완성된 팩 이동 안내도 표시하지 않는다. 통계 저장값과 실제 재고 계산은 유지한다.

수확과 포장 재고는 현재 브라우저의 로컬 저장소에 저장한다. 기기 간 재고 공유 기능은 아직 없다. 코드의 클라우드 저장과 게임 재고 동기화는 별개다.

### 동시 접속

사용자가 Firebase 익명 로그인과 Realtime Database 사용을 승인했다. 브라우저 세션별 이름, 위치, 방향, 행동, 바구니 수량, 현재 공간을 공유한다. 접속자는 자신의 상태만 쓸 수 있다. 접속 종료 처리를 등록하고 연결이 끊기면 해당 상태를 지운다. 데이터 규칙은 `database.rules.json`에 있다.

운영과 개발의 접속자는 분리한다. `strawberry-village.web.app`과 `strawberry-village.firebaseapp.com`만 `village/environments/production`을 사용하고, localhost·LAN·클라우드 개발 주소와 정적 빌드 미리보기 등 나머지 호스트는 `village/environments/development`를 사용한다. 각 환경 아래의 `players`와 `speech`에서 인원·캐릭터·닉네임·대화를 따로 공유한다. 이전 공용 경로 `village/players`와 `village/speech`는 읽거나 쓰지 않으며 새 데이터 규칙에서도 차단한다. 규칙 배포 및 이전 경로 정리는 `docs/RELEASES.md`의 접속자 경로 전환 절차를 따른다.

접속 상태는 가만히 있어도 5초마다 갱신하고, 30초 이상 갱신되지 않은 세션은 인원과 캐릭터에서 제외한다. 페이지를 떠나면 추가 갱신을 멈추고 자신의 상태만 삭제한다. 뒤로 가기 캐시에서 복원되면 다시 등록한다. 종료 중이던 비동기 쓰기가 끝나더라도 상태가 되살아나지 않도록 다시 삭제한다.

이름은 햇살 한 줌, 딸기향 오후, 산들바람 같은 읽을 수 있는 한국어 문구로 한다. 임의의 16진수 문자열을 표시하거나 농부라는 접미사를 강제하지 않는다. 접속 인원과 마을 연결 중 표시가 계속 번갈아 깜빡이지 않도록 현재의 연결 확인과 재시도 처리를 유지한다. 다른 실내에 있는 사람은 같은 화면에 표시하지 않는다.

설정에서 1~16자 닉네임을 변경한다. 접속자 스냅샷을 읽은 뒤 참가하고, 동시 접속 중복은 세션 정렬을 바탕으로 다른 자연스러운 이름을 골라 구분한다. 숫자 접미사를 자동으로 붙이지 않는다. 기본 이름 목록이 겹치면 짧은 한국어 풍경 문구를 조합한다. 예전 기본 이름 뒤에 자동으로 붙었던 숫자는 새 이름 저장 버전으로 옮길 때 제거하고 중복을 다시 해소한다. 사용 중인 이름을 직접 선택하면 변경을 거부하고 비어 있는 다른 이름을 제안한다. 이름표는 안개와 화면의 밝은 막에 흐려지지 않는 진한 HTML로 표시한다. 이 기능은 앱의 세션 집계와 표시 계층에서 처리하며 별도의 서버 예약 레지스트리는 사용하지 않는다. 접속 수는 사람 수가 아닌 브라우저 세션 수이며 같은 환경의 세션만 집계한다.

바깥에 추가한 하우스 두 동의 공유 공간은 기존 규칙과 호환되게 outside로 전송하고 새 클라이언트가 좌표에서 해당 하우스를 판별한다. 확장 좌표는 v2 세션의 전송 시 x를 2, z를 3으로 나누어 기존 데이터베이스 범위 안에 보낸다. 새 클라이언트는 이를 복원하며 이전 세션의 원래 좌표도 읽는다. 이전 클라이언트는 새 전송 형식을 해석하지 못하므로 서로 다른 버전 사이에서는 방문자 위치가 다르게 보일 수 있다. 점프의 세로 움직임은 로컬 동작이며 다른 방문자의 높이는 지형으로 계산한다.

### 주변 대화

같은 공간에서 5 단위 이내의 다른 방문자가 있으면 하단 행동에 말 걸기가 나타난다. 번호는 현재 버튼 순서를 따른다. 말 걸기는 중앙 모달 대신 오른쪽의 작은 채팅창을 열며 마을 이동이나 시점 조작을 멈추지 않는다. 입력창에 포커스가 있을 때는 숫자 행동키를 실행하지 않는다. 닫기 버튼이나 Escape로 닫는다. 공개적인 주변 대화이며 여러 사람이 함께 말풍선을 보고 대화한다. 메시지는 200자까지, 캐릭터 위 말풍선은 12초간 보인다. 여러 이름표·말풍선과 지도·조작 UI를 피해서 배치하고, 원래 캐릭터 위치까지 연결선을 표시한다. 이번 접속에서 들은 최근 대화는 5분·50개 범위로 화면에서 유지한다. 멀리 있는 사람이나 다른 실내 사람의 새 메시지는 표시하지 않는다.

Realtime Database의 `village/environments/$environment/speech/$uid/$session`에 현재 말풍선을 저장한다. 인증된 세션은 해당 환경의 공개 대화 경로를 읽을 수 있고, 쓰기는 같은 환경에 접속 중인 자기 UID의 세션만 가능하다. 거리와 공간에 따른 표시는 클라이언트에서 제한한다. 다른 사람의 이름이나 메시지를 쓸 수 없으며 종료 시 자기 말풍선도 제거한다. 메시지 시각은 서버 시간 차이를 적용한 숫자로 한 번 정해 전송한다. 서버 타임스탬프의 로컬 예상값과 확정값이 달라 같은 메시지가 두 번 기록되는 문제를 막는다. 연속 제출은 입력창과 전송 계층에서 잠그며, 나중에 같은 문장을 다시 보낸 것은 별도 메시지로 유지한다. 정적 사이트 게시와 별개로 새 데이터 규칙 배포가 필요하다. 규칙 미배포·연결 실패는 대화 UI에 연결 불가 상태로 표시하며 기존 이동·재고 기능을 막지 않는다.

### 날씨와 시야

날씨는 논산의 현재 날씨 자료를 Open-Meteo에서 가져온다. 고정 좌표는 36.20389, 127.08472이며 사용자의 실제 위치 권한은 요청하지 않는다. 사용자가 날씨나 낮밤을 임의로 바꾸지 않는다. 모델 기반 현재 날씨 자료이므로 현장 관측 센서 데이터라고 설명하지 않는다.

화면에는 위치명 논산을 표시하지 않는다. 상단에는 날씨 상태와 기온을 보여주되, 설정에는 현재 날씨, 습도, 바람, 강수량을 표시하지 않는다. 날씨와 낮밤에 맞춰 마을이 바뀐다는 설명, 기준 시각과 Open-Meteo 출처 문구도 표시하지 않는다. 움직임 줄이기 옵션은 UI에 추가하지 않는다. 운영체제의 관련 선호는 자동 적용한다.

마을과 모든 실내는 캐릭터가 보이는 가까운 3인칭 추적 시점이다. 카메라는 캐릭터를 항상 중심에 두고 이동·지형·점프·앉기·눕기를 따라간다. 드래그로 캐릭터 주위를 회전할 수 있지만 화면을 따로 밀어 이동하는 팬 기능은 없다. 방향키는 바라보는 방향을 기준으로 이동하고, 바닥 클릭 경로 이동도 유지한다. 기본 카메라 거리는 7.5이며 휠·핀치·확대 버튼의 거리는 3~18, 일반 실내에서는 최대 8로 제한한다. 카페는 외부 건물과 분리된 너비 24·깊이 21·높이 7.5의 넓은 실내를 사용한다. 입구를 지나면 실내의 빈 바닥으로 이어지고, 안쪽 카운터에 다가가면 주문하며, 정면 중앙 문으로 나가면 외부 테라스로 돌아온다. 카페 카메라는 거리 6~16과 거리별 시야각(데스크톱 70~90도, 모바일 74~94도)을 사용하므로 실내에서도 축소할 수 있다. 출입구를 통해 카메라가 실내 밖으로 빠져나가지는 않는다. 카페 외관의 차폐와 지붕은 유지한다. 더 넓게 축소해도 중심은 캐릭터에 고정하고, 기존에 저장한 확대 정도는 유지한다. 캐릭터는 이동 방향을 바라보고 카메라 회전만으로 몸이 돌아가지 않는다. 자신의 아바타·이름표와 다른 방문자를 표시한다. 카메라는 불투명한 건물·천장과 오르막 지형 앞에서 거리를 줄인다. 베드 살펴보기도 캐릭터를 중심에 둔 가까운 시점으로 바뀌며 종료하면 이전 회전을 복원한다. 기존 위치·자세·재고는 유지하고 이전 카메라 모드의 거리는 새 기본값으로 바꾼다.

카페는 외부에서 실내가 보이지 않아야 한다. 전면 벽·창·지붕 양 끝과 천장을 막고, 중앙 문은 실내 전환 전까지만 닫힌 모습으로 표시한다. 카운터·집기·점원은 카페 실내에서만 보인다. 앞쪽 창과 벽에는 충돌이 있으며 중앙 문으로만 걸어 들어간다.

## 실행과 확인

Node.js 22.13 이상에서 `npm ci` 후 `npm run dev`를 실행한다. 기본 주소는 http://127.0.0.1:5173/ 이다. `npm run build`는 Firebase와 클라우드 저장 버전에서 공통으로 쓰는 정적 `build/` 폴더를 생성한다.

개발 서버는 Vite HMR과 React Fast Refresh를 사용한다. 클라우드 파일 시스템에서도 변경을 감지하도록 파일 감시에 300ms 폴링을 사용한다.
클라우드 미리보기에서 접근할 수 있도록 `0.0.0.0:5173`에서 수신하며, 브라우저 주소는 `http://127.0.0.1:5173/`을 사용한다. 개발 응답은 캐시하지 않는다.
클라우드 환경의 localhost와 사용자 기기의 localhost는 서로 다른 서버다. 클라우드에서 개발 서버를 실행한 것으로 사용자 기기의 로컬 화면이 갱신되었다고 안내하지 않는다. 로컬 화면을 갱신하려면 해당 기기의 저장소에 변경 브랜치를 받아 그 기기의 서버에서 실행해야 한다.
`/__dev/status`는 3D와 React를 사용하지 않는 개발 전용 연결 확인 화면이다. 이 화면까지 비어 있다면 앱 기능보다 브라우저 미리보기의 서버 연결을 먼저 확인한다. 프로덕션 빌드에는 이 경로를 포함하지 않는다.

타입 검사: `node node_modules/typescript/bin/tsc --noEmit`

접속 분리 검사: `node scripts/validate-presence-isolation.mjs`. 운영·개발·미리보기 주소의 구분, 이전 공용 데이터 제외, 환경별 인원, 30초 만료와 잘못된 타임스탬프·좌표를 확인한다. `validate-presence.mjs`에서도 두 환경의 인원·닉네임·대화 분리를 함께 검증한다.

클릭 이동 경로 검사: `node scripts/validate-navigation.mjs`. 직선 이동, 범위 제한, 장애물 클릭, 얇은 벽 우회, 베드 사이 좁은 통로, 도달 불가능한 위치를 확인한다.

마을 상태 검사: `node scripts/validate-village.mjs`. 닉네임 중복 해소와 입력 순서 독립성, 좌표 전송 호환과 범위, 산 지형의 연속성과 오르막 산책길을 확인한다.

재고 검사: `node scripts/validate-inventory.mjs`

검사 범위는 불완전하거나 중복된 선택 거부, 없는 딸기 거부, 원자적인 포장, 같은 딸기 중복 소비 방지, 카페에서 팩을 열어 소비하고 남은 낱알을 보존하는지, 이전 저장 데이터 변환이다.

타입·재고·경로·마을 상태·대화 조건 검사와 정적 빌드를 확인한다. `validate-presence.mjs`는 모의 Firebase 전송으로 세 방문자의 중복 이름 처리, 닉네임 변경 거부, 주변 메시지 전파, 거리·공간 필터, 발송 간격, 말풍선 만료와 종료 정리를 검증한다. 이 검사는 실제 Firebase 규칙 엔진 실행을 대신하지 않는다.

실제 브라우저에서 하우스 밖 행동 숨김, 새 하우스 위치 복원, 12칸 포장과 혼합 팩의 카페 계산, 설정과 동일 높이 카드, 로고 제거, 모바일·데스크톱 아이콘 지도, 변경된 마우스·터치 조작과 말풍선 UI를 확인했다. 모의 전송으로 대화 입력과 수신 표시를 확인했다. 하우스 앞뒤 문 통과·옆벽 충돌과 짧은 모바일 모달의 드래그 스크롤도 확인했다. 기능 검사에서는 렌더링 부하를 분리했고 실제 렌더러로 각 공간을 별도로 확인했다. 자동 검사는 외부 인증을 막아 실제 방문자를 만들지 않았다.

PR 검증과 Release 배포 전에는 GitHub Actions에서 실제 Firebase 에뮬레이터로 `validate-database-rules.mjs`를 실행한다. PR 준비 당시 로컬 Firebase 규칙 엔진용 에뮬레이터 다운로드는 네트워크 정책으로 차단돼 실행하지 못했다. 당시에는 관리자 인증과 실제 규칙 배포, 기존 다른 세션의 강제 종료 및 공개 서비스 배포를 진행하지 않았다. 이후 실제 관리자 적용과 다중 접속 검증 결과는 아래에 기록한다. Release는 게시하지 않았다.

접속 분리 변경은 타입·접속 분리·재고·이동 경로 검사와 정적 빌드를 통과했다. 테스트용 Firebase SDK와 로컬 소스로 운영 호스트를 재현한 브라우저 검사에서 이전 접속자 10개 제외, 운영 1명·개발 2명의 인원과 캐릭터 분리, 종료 전 연결 해제 등록, 페이지 종료·복원, 종료 중 쓰기 완료 후 재삭제와 세션 정리를 확인했다. 3D를 포함한 화면 검사 프로세스는 메모리 제한으로 중단되어 접속 동작을 분리한 검사로 확인했다. PR 준비 당시 실제 데이터베이스 공용 경로에는 접속 상태 10개가 있었고 새 개발 경로 접근이 거부되었다. 당시 관리자 인증이 없어 규칙 배포·이전 상태 삭제·Hosting 배포를 완료하지 못했다. 공개 사이트 접속도 환경 네트워크 정책의 HTTP 403으로 차단되었다.

### 2026년 11월 8일 실제 서버 적용

사용자가 현재 접속만 종료하고 계정은 유지하도록 요청했다. 운영·개발 접속자/닉네임/대화 분리 수정안은 PR #3으로 main의 `50a612b`에 병합되어 있다. 이 환경의 이전 소스를 해당 main까지 fast-forward했고, 게임 조작이나 UI에 새로운 변경을 추가하지 않았다.

관리자 CLI 인증과 프로젝트 접근을 확인한 뒤 `database:village` 규칙을 실제 Firebase에 배포했다. 배포 직전 공용 `village/players`에는 최근 30초 이내에 갱신된 세션 12개가 있었다. 새 규칙으로 이전 공용 경로의 클라이언트 읽기·쓰기를 먼저 차단한 뒤, `village/players`와 `village/speech`의 일시적 상태를 삭제했다. 기존 Authentication 계정 삭제·비활성화·토큰 취소·관리자 로그아웃은 수행하지 않았다. 브라우저 재고도 수정하지 않았다. 복구용 이전 규칙과 일시적 접속 상태는 저장소 밖의 비공개 작업 파일로 보관했다.

실제 Firebase 인증을 사용하는 임시 계정 네 개로 운영 두 명·개발 두 명을 접속시켜 실제 Realtime Database에서 35개 검증을 통과했다. 환경별 접속자와 같은 닉네임, 대화가 분리되며, 미인증 읽기·다른 계정 사칭·다른 환경의 접속을 이용한 발언·이전 공용 경로와 알 수 없는 환경의 읽기 및 쓰기가 거부된다. 검사 뒤 임시 계정 네 개와 해당 접속/대화 상태를 정리했고, 이전 공용 상태가 재생성되지 않음을 재확인했다. 이는 실제 데이터베이스 규칙과 데이터 전송 검사이며 공개 사이트의 배포 완료를 뜻하지 않는다.

실제 Firebase SDK와 현재 `connectVillage` 소스를 사용하는 Chromium 검사도 13개 항목을 통과했다. 검증용 번들에서 호스트별 환경 선택을 고정하고 실제 데이터베이스에 운영 두 명·개발 두 명을 접속시켜 접속 인원/캐릭터/같은 닉네임/대화의 분리, 같은 환경 내 중복 닉네임 거부, 전송 중 페이지 종료 후 5.6초가 지나도 접속이 재생성되지 않는지, 접속 종료 뒤 인증 계정 유지, 다른 환경 접속 유지와 페이지 복원 시 같은 환경 재접속을 확인했다. 추가로 만든 검사 계정 네 개는 검사 후 삭제했다. 3D 렌더링을 제외한 접속 로직 검사이며, 아직 배포되지 않은 공개 Hosting 버전을 검증한 것은 아니다. Chromium의 제공된 프록시 CA 저장소가 샌드박스에서 읽기 전용이라 기본 실행에서 인증서 오류가 발생했으며, 승인된 샌드박스 밖 실행에서 TLS 검증을 유지해 실제 인증/전송 검사를 수행했다.

타입·접속 분리·접속 전송·대화·재고·이동 경로·마을 상태 검사와 정적 빌드가 통과했다. 클라우드 개발 서버는 최신 main으로 실행 중이다. 사용자 기기의 로컬 서버를 갱신한 것은 아니다.

운영 Hosting 배포와 공개 주소 검증은 환경 네트워크 정책으로 막혀 아직 완료하지 못했다. 기존 허용 도메인은 보존하고 `api.github.com`, `firebasehosting.googleapis.com`, `upload-firebasehosting.googleapis.com`, `strawberry-village.web.app`, `strawberry-village.firebaseapp.com`을 환경 설정 초안에 추가해 저장했다. 도구는 초안만 저장하며 실제 정책에는 적용하지 않는다. 사용자가 환경 설정을 검토·저장하고 환경을 게시한 뒤, 새 정책을 확인하고 Hosting `village`를 배포해야 한다. GitHub Release나 Sites는 게시하지 않았다. Hosting 배포 전의 기존 웹사이트 버전은 차단된 공용 접속 경로를 계속 사용하므로 최신 클라이언트 배포 후 새로고침이 필요하다.

### 미리보기 접속 복구와 가까운 3인칭 변경

Sites의 이전 게시 버전은 차단된 공용 `village/players` 경로를 사용해 “마을 연결 중”에 머물렀다. GitHub의 최신 환경 분리 코드를 미리보기에도 반영한다. 같은 출처의 `/dev/` 진입점을 빌드에 포함하므로 새 확인용 경로에서도 해당 브라우저의 재고 저장소를 유지한다.

`node scripts/validate-world-actions.mjs`는 실제 월드 로직과 지오메트리에 렌더러만 대체해 캐릭터 표시·드래그 중심 유지·음료 애니메이션·이동 및 모달 취소·중복 소비 방지·움직임 줄이기·접속 규칙 호환을 검증한다.

`node scripts/validate-follow-camera.mjs`는 캐릭터 중심 유지·드래그 회전·이동 추적·거리 제한·벽과 천장 및 지형 충돌·시점 복원을 검증한다. `node scripts/validate-cafe.mjs`는 외부에서의 전면·측면·후면·지붕 차폐와 중앙 문 통과, 창 충돌을 실제 Three.js 지오메트리로 확인한다. 접속 모의 전송 검사에서는 로컬 예상 시각과 서버 확정 시각이 다른 상황의 중복 방지, 의도적인 같은 문장 재전송, 개발 전용 테스트 이웃의 응답과 실제 접속 인원 제외를 확인한다. 이 작업의 클라우드 미리보기 릴레이는 포트 4173 준비 시간 초과로 실행되지 않아 로컬 브라우저 시각 검증은 별도 확인이 필요하다. 공개 Firebase Hosting과 규칙은 변경하지 않는다.
